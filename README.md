# DeepLister · AI深度倾听式调研Agent

> 一个会追问的AI调研员——基于Harness架构，让AI的追问可控、可检查、可修正、可迭代。

## 为什么做这个

五一期间陪姑姑去西京医院做心理测评，观察到一个真实问题：**主观感受类问卷的理解偏差和表达偏差，比想象中大得多。**

- 文化程度偏低的中老年人，读不懂"偶尔""经常""严重"的书面表述
- 即便读懂了，每个人对这些词的定义也不一样
- 传统问卷无法纠正这些偏差，深度访谈可以但成本太高

**有没有一种方式，能融合问卷的效率与访谈的深度？**

DeepLister的回答是：**不是让AI自由追问，而是用Harness系统让追问变得可控。**

## 它怎么工作

传统AI对话产品的思路是"给模型一个prompt，让它自己决定怎么追问"。问题在于——模型什么时候追问、怎么追问、追问质量好不好，全都不可控。

DeepLister把追问拆成**四步编排**：

```
用户说了一句话
    ↓
Step 1 检测：这句话有没有"问题"？
    ├── 理解偏差（回答含糊/误解题意）
    ├── 信息不足（只有结论没有原因）
    ├── 前后矛盾（和之前说的不一致）
    └── 安全信号（自伤/崩溃倾向）
    ↓
Step 2 仲裁：该用哪种策略处理？
    ├── 优先级排序：安全 > 理解 > 矛盾 > 信息不足
    └── 纯代码规则，不走AI，保证确定性
    ↓
Step 3 生成：按策略生成追问
    └── 追问不超过2句话，语气自然不带审讯感
    ↓
Step 4 校验：追问质量过关吗？
    ├── 策略一致？没重复？不超长？安全？
    └── 不通过则修正，通过才输出给用户
```

**这四步不是让模型"自由发挥"，而是系统在每一步引导模型做对的事。**

这就是Harness思维和Prompt思维的核心区别：
- Prompt思维：模型+prompt+对话界面，生成完就结束
- Harness思维：信息边界+执行编排+评估校验+数据闭环，生成后有验收机制

## 与"让AI自由追问"的区别

| | 让AI自由追问 | DeepLister的四步编排 |
|---|---|---|
| 什么时候追问 | 模型自己决定 | 检测层判断，仲裁层选策略 |
| 追问质量 | 不可控 | 校验层把关，不通过就修正 |
| 追问太多 | 可能无限追问 | 仲裁层硬上限3轮 |
| 追问重复 | 可能反复问 | 校验层检测重复，强制换角度 |
| 出错了怎么修 | 重新生成 | 定位问题、局部修正 |
| 能不能迭代 | 无法积累经验 | 每轮决策链路完整记录，数据闭环 |

## 关键设计决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 仲裁层用代码不用LLM | 纯规则 | 确定性优先——优先级逻辑不能交给概率模型 |
| 检测和生成分开 | 两个独立步骤 | 检测需要低温度保证稳定，生成需要适当温度保证自然 |
| 校验层在生成之后 | 先生成后检查 | 不是生成就结束，而是生成后有验收机制 |
| 信息边界按需加载 | 每步只传最小必要上下文 | 避免全量历史导致判断泛化+降低API成本 |
| Streamlit而非React | 纯Python | 核心目标是验证引擎有效性，不是构建生产级Web服务 |
| 评估与代码同步 | evaluation模块内置 | 设计-开发-评估闭环，不是做完才想怎么测 |

## 技术栈

- **界面**：Streamlit（纯Python，零前端经验要求）
- **LLM**：OpenAI GPT-4o-mini（运行期）+ MockLLM（Demo/评估期）
- **数据**：Pydantic模型 + JSON文件持久化
- **评估**：内置evaluation模块，15组标准场景 + 4项核心指标
- **不使用LangChain**：Harness的四步编排是自定义流程，减少依赖=减少不确定性
