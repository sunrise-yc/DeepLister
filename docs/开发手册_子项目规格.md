### 复制以下内容交给AI工具

---

你是Python开发者。请为DeepLister项目生成全局基础模块，包含3个文件。

**项目背景：** DeepLister是一个AI调研Agent，在问卷执行中动态追问用户。核心架构是Harness四步编排：检测→仲裁→生成→校验。用Streamlit做界面，OpenAI API做LLM调用，JSON文件做数据持久化。

### 文件1：shared/types.py

定义所有模块共享的数据类型，使用Pydantic BaseModel。其他模块通过 `from shared.types import XXX` 导入。

需要定义以下类型：

```python
from typing import Optional
from pydantic import BaseModel

# --- 信号检测结果 ---

class SignalResult(BaseModel):
    """单类信号的检测结果"""
    triggered: bool
    type: Optional[str] = None  # 信号子类型
    detail: Optional[str] = None  # 触发原因描述
    confidence: float = 0.0  # 0-1，模型对此次检测的置信度

class SignalDetection(BaseModel):
    """四类信号的并行检测结果"""
    safety: SignalResult          # P0: 自伤/崩溃/抗拒
    comprehension: SignalResult   # P1: 理解偏差（含糊/误解）
    consistency: SignalResult      # P2: 前后矛盾
    sufficiency: SignalResult      # P3: 信息不足（只有结论无原因）

# --- 仲裁结果 ---

class ArbitrationResult(BaseModel):
    """策略仲裁的输出"""
    strategy: str  # safety_protocol | comprehension_correction | consistency_confirmation | depth_mining | proceed | transition | skip_topic
    priority: str  # P0 | P1 | P2 | P3 | P4
    follow_up_count: int  # 当前话题累计追问轮次
    force_proceed: bool = False  # 是否强制推进（达到上限时）

# --- 校验结果 ---

class VerificationResult(BaseModel):
    """质量校验的输出"""
    passed: bool
    strategy_consistency: bool = True  # 生成内容是否执行了仲裁策略
    repetition_check: bool = True     # 是否与最近2轮重复
    length_check: bool = True         # 是否≤2句话
    safety_check: bool = True         # 是否安全
    correction_direction: Optional[str] = None  # 不通过时的修正方向

# --- 话题状态 ---

class TopicStatus(BaseModel):
    """单个话题在画像中的状态"""
    status: str = "not_started"  # not_started | in_progress | completed | skipped
    core_dimensions_covered: list[str] = []
    key_signals: list[str] = []
    follow_up_count: int = 0
    completeness_score: float = 0.0
    current_sub_question: Optional[str] = None

# --- 一致性标记 ---

class ConsistencyFlag(BaseModel):
    """跨话题一致性问题的标记"""
    topic_pair: list[str]  # 涉及的两个话题ID
    description: str
    resolved: bool = False

# --- 会话记录 ---

class SessionRecord(BaseModel):
    """单次会话的摘要记录"""
    date: str
    topics_completed: list[str] = []
    duration_minutes: int = 0

# --- 用户画像 ---

class UserProfile(BaseModel):
    """跨会话持久化的用户画像，每轮对话都在读写"""
    user_id: str
    cognitive_level: str = "medium"  # low | medium | high
    communication_preference: str = "prefer_concrete_examples"  # prefer_concrete_examples | prefer_abstract | prefer_brief
    topics_status: dict[str, TopicStatus] = {}
    consistency_flags: list[ConsistencyFlag] = []
    session_history: list[SessionRecord] = []

# --- 决策日志单条 ---

class DecisionLogEntry(BaseModel):
    """一轮对话的完整决策链路"""
    turn_id: int
    user_reply: str
    detection_result: SignalDetection
    arbitration_result: ArbitrationResult
    generated_reply: str
    verification_result: VerificationResult
    evaluation: Optional[dict] = None  # 追问有效性评估

# --- 问卷结构 ---

class SubQuestion(BaseModel):
    """话题下的子问题"""
    question_id: str
    text: str
    dimension: str  # 对应core_dimensions中的哪个维度

class Topic(BaseModel):
    """问卷拆解后的话题单元"""
    topic_id: str
    topic_name: str
    description: str
    core_dimensions: list[str]
    opening_question: str
    sub_questions: list[SubQuestion] = []

class Questionnaire(BaseModel):
    """研究者上传的问卷"""
    title: str
    description: str
    topics: list[Topic]
```

### 文件3：shared/llm_client.py

封装LLM调用，支持OpenAI和Ollama两种provider，统一接口。

```python
from shared.config import Config

class LLMClient:
    """统一的LLM调用客户端"""
    
    def __init__(self, provider: str = None):
        self.provider = provider or Config.LLM_PROVIDER
        self._openai_client = None
    
    @property
    def openai_client(self):
        """懒加载OpenAI客户端"""
        if self._openai_client is None:
            from openai import OpenAI
            self._openai_client = OpenAI(
                api_key=Config.OPENAI_API_KEY,
                base_url=Config.OPENAI_BASE_URL
            )
        return self._openai_client
    
    def chat(self, messages: list[dict], temperature: float = 0.7, max_tokens: int = 1000) -> str:
        """
        统一的聊天接口
        Args:
            messages: OpenAI格式的消息列表 [{"role": "system/user/assistant", "content": "..."}]
            temperature: 生成温度
            max_tokens: 最大生成token数
        Returns:
            模型的文本回复
        """
        if self.provider == "openai":
            response = self.openai_client.chat.completions.create(
                model=Config.OPENAI_MODEL,
                messages=messages,
                temperature=temperature,
                max_tokens=max_tokens
            )
            return response.choices[0].message.content
        
        elif self.provider == "ollama":
            import requests
            response = requests.post(
                f"{Config.OLLAMA_BASE_URL}/api/chat",
                json={
                    "model": Config.OLLAMA_MODEL,
                    "messages": messages,
                    "stream": False,
                    "options": {"temperature": temperature}
                }
            )
            return response.json()["message"]["content"]
        
        else:
            raise ValueError(f"Unknown LLM provider: {self.provider}")
    
    def chat_json(self, messages: list[dict], temperature: float = 0.1) -> dict:
        """
        调用LLM并期望返回JSON格式
        在messages中提示模型输出JSON，解析返回结果
        如果解析失败，返回空dict并打印警告
        """
        import json
        text = self.chat(messages, temperature=temperature)
        # 尝试从markdown代码块中提取JSON
        if "```json" in text:
            text = text.split("```json")[1].split("```")[0].strip()
        elif "```" in text:
            text = text.split("```")[1].split("```")[0].strip()
        try:
            return json.loads(text)
        except json.JSONDecodeError:
            print(f"[WARNING] LLM返回的内容无法解析为JSON: {text[:200]}")
            return {}
```

## 子项目1：问卷解析模块

> 依赖：子项目0（shared/types.py）

### 复制以下内容交给AI工具

---

你是Python开发者。请为DeepLister项目生成问卷解析模块。

**项目背景：** DeepLister是一个AI调研Agent，核心流程是：研究者上传问卷JSON → 引擎解析为话题序列 → 受访者逐话题对话。

**你的任务：** 生成 `core/questionnaire_parser.py`，将问卷JSON解析为结构化的话题序列。

**已有的共享类型（在shared/types.py中，可直接import）：**

```python
from shared.types import Questionnaire, Topic, SubQuestion
```

### 功能要求

1. **parse_questionnaire(json_data: dict) -> Questionnaire**
   - 输入：问卷的原始JSON dict
   - 输出：Questionnaire对象（Pydantic模型）
   - 做字段校验：topics不能为空，每个topic必须有topic_id/topic_name/opening_question/core_dimensions
   - 如果sub_questions为空，自动根据core_dimensions生成子问题（格式："关于{dimension}，能具体说说吗？"），并分配递增的question_id（如 topic_id + "_sq1"）

2. **get_next_topic(questionnaire: Questionnaire, completed_topic_ids: list[str]) -> Optional[Topic]**
   - 输入：问卷 + 已完成的话题ID列表
   - 输出：下一个未完成的话题，如果没有则返回None
   - 按topics列表顺序返回

3. **get_next_sub_question(topic: Topic, answered_question_ids: list[str]) -> Optional[SubQuestion]**
   - 输入：当前话题 + 已回答的子问题ID列表
   - 输出：下一个未回答的子问题，如果没有则返回None

4. **validate_questionnaire(json_data: dict) -> tuple[bool, str]**
   - 输入：问卷原始JSON
   - 输出：(是否合法, 错误信息)
   - 检查：title非空、topics非空、每个topic有必填字段

### 代码规范

- 每个函数写docstring，说明输入输出和异常情况
- 使用Pydantic的model_validate进行解析，利用Pydantic自身的校验能力
- 不要使用LLM，这是纯逻辑模块

## 子项目2：检测层（Detector）

> 依赖：子项目0（shared/types.py, shared/llm_client.py）

### 复制以下内容交给AI工具

---

你是Python开发者。请为DeepLister项目生成检测层模块。

**项目背景：** DeepLister是一个AI调研Agent，基于Harness架构。核心流程是四步编排：检测→仲裁→生成→校验。你的任务是实现第一步——信号检测。

**检测层的职责：** 分析用户回复，并行检测四类信号，输出结构化结果。检测层只做判断，不做生成。

**已有的共享类型（在shared/types.py中，可直接import）：**

```python
from shared.types import SignalDetection, SignalResult
```

**已有的LLM客户端（在shared/llm_client.py中，可直接import）：**

```python
from shared.llm_client import LLMClient
```

### 功能要求

1. **class Detector**
   - 构造函数：`__init__(self, llm_client: LLMClient = None)`
   - 如果未传入llm_client，自动创建一个

2. **detect(self, user_reply: str, current_question: str, topic_context: dict, user_profile: dict) -> SignalDetection**
   - 输入：
     - user_reply: 用户本轮回复文本
     - current_question: 当前正在问的问题文本
     - topic_context: 当前话题上下文，包含 topic_name, core_dimensions, key_signals(已提取的关键信号), previous_replies(最近2轮用户回复)
     - user_profile: 用户画像摘要，包含 cognitive_level, communication_preference
   - 输出：SignalDetection对象（包含四类信号的结果）
   - 内部实现：构造一个system prompt + user prompt，调用LLM，要求输出JSON格式的四类信号检测结果

### Prompt设计要求

**System Prompt核心内容：**

```
你是一个信号检测器，你的唯一任务是分析用户回复，判断是否存在以下四类信号。
你只做判断，不做追问，不做建议。

四类信号：
1. safety（安全信号）：用户表达自伤/自杀倾向、严重情绪崩溃、或明确抗拒继续
   子类型：self_harm | emotional_crisis | resistance
2. comprehension（理解偏差）：用户没有理解问题，或回答含糊无法提取有效信息
   子类型：vague_reply（回答含糊如"还行""差不多"）| misunderstanding（答非所问）| confusion（明确表示不理解）
3. consistency（前后矛盾）：用户当前回答与之前同一话题内的表述矛盾
   子类型：factual_contradiction（事实性矛盾）| rating_shift（评分/程度明显变化但无解释）
4. sufficiency（信息不足）：用户给了结论但没有原因、场景、影响等支撑
   子类型：conclusion_without_reason（只有结论无原因）| frequency_unclear（频率模糊）| impact_missing（影响未提及）

输出格式（严格JSON）：
{
  "safety": {"triggered": bool, "type": "子类型或null", "detail": "触发原因或null", "confidence": 0.0-1.0},
  "comprehension": {"triggered": bool, "type": "子类型或null", "detail": "触发原因或null", "confidence": 0.0-1.0},
  "consistency": {"triggered": bool, "type": "子类型或null", "detail": "触发原因或null", "confidence": 0.0-1.0},
  "sufficiency": {"triggered": bool, "type": "子类型或null", "detail": "触发原因或null", "confidence": 0.0-1.0}
}

判断原则：
- 宁可漏检也不要误报（confidence < 0.5时不触发）
- safety信号宁误报不漏报（confidence >= 0.3即触发）
- 只有信息明显不足时才触发sufficiency，不要对简短但完整的回答过度触发
- 如果topic_context中有previous_replies，对比检查consistency；如果没有则consistency不触发
```

**User Prompt构造方式：**

```
当前话题：{topic_name}
核心维度：{core_dimensions}
当前问题：{current_question}
用户回答：{user_reply}
{如果有关键信号：已提取的关键信号：{key_signals}}
{如果有前文回复：用户之前说：{previous_replies}}
用户认知水平：{cognitive_level}
```

### 代码规范

- 使用 `llm_client.chat_json()` 方法调用LLM，temperature使用Config.TEMPERATURE_DETECT (0.1)
- 解析LLM返回的JSON，构造SignalDetection对象
- 如果LLM返回的JSON解析失败，返回所有信号triggered=False的默认结果（宁可漏检不要崩溃）
- safety信号的confidence阈值设为0.3（更低），其他信号设为0.5

### 验收标准

能对以下输入返回合理的检测结果：

```python
detector = Detector()
result = detector.detect(
    user_reply="还行吧，也不太好说",
    current_question="最近一周睡眠怎么样？",
    topic_context={"topic_name": "睡眠质量", "core_dimensions": ["入睡难度", "持续时间", "影响程度"], "key_signals": [], "previous_replies": []},
    user_profile={"cognitive_level": "medium", "communication_preference": "prefer_concrete_examples"}
)
assert result.comprehension.triggered == True  # 含糊回答应触发理解偏差
assert result.safety.triggered == False  # 无安全信号
```

## 子项目3：仲裁层（Arbitrator）

> 依赖：子项目0（shared/types.py）
> 注意：纯代码，不使用LLM

### 复制以下内容交给AI工具

---

你是Python开发者。请为DeepLister项目生成仲裁层模块。

**项目背景：** DeepLister是一个AI调研Agent，核心流程是四步编排：检测→仲裁→生成→校验。你的任务是实现第二步——策略仲裁。

**仲裁层的职责：** 接收检测层的信号结果，根据优先级规则选择响应策略。这是纯代码逻辑，不调用LLM，保证100%确定性。

**已有的共享类型（在shared/types.py中，可直接import）：**

```python
from shared.types import SignalDetection, ArbitrationResult
from shared.config import Config
```

### 功能要求

1. **class Arbitrator**
   - 无状态，无需构造函数参数

2. **arbitrate(self, detection: SignalDetection, follow_up_count: int, consecutive_vague: int = 0, user_skip: bool = False) -> ArbitrationResult**
   - 输入：
     - detection: 检测层的四类信号结果
     - follow_up_count: 当前话题已追问轮次
     - consecutive_vague: 连续敷衍回复次数
     - user_skip: 用户是否主动要求跳过
   - 输出：ArbitrationResult

### 仲裁规则（严格按此顺序执行）

```
规则0: user_skip=True → skip_topic
规则1: follow_up_count >= MAX_FOLLOW_UP_PER_TOPIC → proceed (force_proceed=True)
规则2: consecutive_vague >= MAX_CONSECUTIVE_VAGUE → skip_topic
规则3: safety.triggered=True → safety_protocol (P0)
规则4: comprehension.triggered=True → comprehension_correction (P1)
规则5: consistency.triggered=True → consistency_confirmation (P2)
规则6: sufficiency.triggered=True → depth_mining (P3)
规则7: 以上均不满足 → proceed (P4)
```

多信号同时触发时，只执行最高优先级的策略，不叠加。

**特殊判断：** 当follow_up_count == 0且无任何信号触发时，策略应为 `transition`（话题完成，过渡到下一话题）而非 `proceed`。区分方式：proceed表示"继续当前话题的下一个子问题"，transition表示"当前话题已完成，进入下一个话题"。

在ArbitrationResult中：
- strategy: 上述7种策略之一
- priority: 对应的P0-P4
- follow_up_count: 传入的follow_up_count（原样返回，供调用方记录）
- force_proceed: 只在规则1触发时为True

### 代码规范

- 纯函数式逻辑，不调用LLM，不访问外部状态
- 每条规则写成独立的if判断，顺序执行，先匹配先返回
- MAX_FOLLOW_UP_PER_TOPIC 和 MAX_CONSECUTIVE_VAGUE 从 Config 读取
- 写清楚注释，说明每条规则的触发条件

### 验收标准

```python

# 规则3: safety最高优先
det = SignalDetection(
    safety=SignalResult(triggered=True, type="self_harm", confidence=0.8),
    comprehension=SignalResult(triggered=True, type="vague_reply", confidence=0.9),
    consistency=SignalResult(triggered=False),

### Prompt设计

校验使用两次LLM调用（可以合并为一次以提高效率，但分开更精确）：

System Prompt:
```

**已完成的模块（可直接import）：**

### 功能要求

1. **class HarnessEngine**
   - 构造函数：`__init__(self, questionnaire: Questionnaire, profile_manager: ProfileManager, llm_client=None)`
   - 内部初始化：detector, arbitrator, generator, verifier

2. **process_reply(self, user_id: str, user_reply: str) -> dict**
   - 这是核心方法，每轮对话调用一次
   - 返回dict: {"reply": str, "topic_completed": bool, "all_completed": bool, "decision_log": DecisionLogEntry}

   内部流程：
   ```
   Step 0: 加载上下文（信息边界）
     - 从ProfileManager获取用户画像
     - 获取当前话题状态
     - 获取当前问题文本
     - 获取最近2轮的AI回复和用户回复
   
   Step 1: 信号检测
     - 调用detector.detect()
     - 传入最小必要上下文
   
   Step 2: 策略仲裁
     - 调用arbitrator.arbitrate()
     - 传入检测结果 + 追问轮次 + 连续敷衍次数
   
   Step 3: 回复生成
     - 调用generator.generate()
     - 传入策略 + 话题上下文 + 用户画像 + 最近AI回复
   
   Step 4: 质量校验
     - 调用verifier.verify()
     - 如果不通过：根据correction_direction重新生成（最多重试1次）
     - 仍不通过：降级为proceed策略重新生成
     - proceed也不通过：直接用"好的，了解了。"兜底
   
   Step 5: 更新状态
     - 更新话题的follow_up_count
     - 如果策略是transition/skip_topic：标记话题完成
     - 提取关键信号更新到画像
     - 写入决策日志
   
   Step 6: 返回结果
     - reply: 最终输出给用户的文本
     - topic_completed: 当前话题是否完成
     - all_completed: 所有话题是否完成
     - decision_log: 本轮决策日志
   ```

3. **get_opening(self, user_id: str) -> str**
   - 用户开始对话时调用
   - 加载用户画像，获取第一个未完成话题的开场问题
   - 如果所有话题都完成了，返回"感谢您的参与！"

4. **get_status(self, user_id: str) -> dict**
   - 返回当前进度：已完成话题/总话题数，当前话题名

### 信息边界实现

每步调用LLM时，只传入该步骤需要的信息：

| 步骤 | 传入信息 | 不传入 |
|---|---|---|
| 检测 | 当前问题+用户回复+话题名+核心维度+最近2轮+认知水平 | 其他话题的对话历史 |
| 仲裁 | 检测结果+追问轮次+连续敷衍次数 | 不需要任何对话内容 |
| 生成 | 策略+话题上下文+画像+最近AI回复 | 检测层的原始输出 |

- process_reply方法内部用清晰的Step注释标注每步
- 每步的输入输出都打印到日志（用python logging）
- 异常处理：任何步骤抛异常时，降级为"好的，了解了。"回复，不崩溃
- consecutive_vague的计算：如果检测结果comprehension.triggered且type为vague_reply，则+1，否则归零
